## Context

On November 7–8, 2026, the project's dependencies were scanned with Trivy 0.76.2, with npm audit as a cross-check against a second advisory database.
Trivy was downloaded from the official GitHub release, avoiding the versions affected by Trivy's March 2026 supply-chain incident.
The scan covered all three workspaces (api, web, speech) through the single root `package-lock.json`.
Trivy first generated a CycloneDX SBOM (`sbom.cdx.json`) listing the packages that ship, then ran two vulnerability scans: one on shipped packages only, and one including development dependencies.
Out of scope: the project's own source code (Trivy checks third-party packages only), the separate test-framework repository, and container images, since none are built yet.

## Findings

The first scan included development dependencies but showed only high and critical findings: four high.
After those were fixed, a full scan at every severity found one medium finding, minimatch. npm audit reported the same issue as nine entries, because it counts every package in the chain.

| Package | Version | ID | Severity | Issue | Pulled in by |
|---|---|---|---|---|---|
| body-parser | 2.3.0 | CVE-2026-111181 | High | Denial of service via decompression error | Pact (API contract tests) |
| follow-redirects | 1.16.1 | CVE-2026-116689 | High | Information disclosure on cross-origin redirects | Pact (via axios, http-proxy) |
| vite | 8.3.1 | CVE-2026-112942 | High | Command injection in the dev server's open-in-editor feature | Web build tooling, Vitest |
| source-map-js | 1.2.1 | CVE-2026-93749 | High | Denial of service via malformed source maps | postcss, inside vite |
| minimatch | 10.2.6 | CVE-2026-118764 | Medium | Denial of service via crafted glob pattern | typescript-eslint (API) |

`npm ls --omit=dev` returned nothing for these packages, confirming that none of them ship.
The minimatch copy that does ship (11.0.5, through `@fastify/static`) was already on a fixed version.

## Decision

Releases will be gated on high and critical findings. Medium and low findings are reviewed on a schedule instead of blocking a release.
The four high findings were fixed with `npm audit fix`, which upgrades to patched versions within each package's allowed version range. Lint, typecheck and build pass on the new versions, and a re-scan reports none. Two R-07 tests that failed during this check predate the change (they fail identically on the old lockfile) and are fixed separately in PR #22.
`npm audit fix --force` was tried and reverted: it moved typescript-eslint to a different major version and offered a further downgrade.
For minimatch, a scoped npm override forcing version 11 under typescript-eslint was tested and reverted, because npm did not apply it at that depth without regenerating the whole lockfile.
The minimatch finding is accepted: it is limited to linting, which only reads glob patterns from the project's own configuration, and it is recorded in `.trivyignore` with an expiry date.

## Consequences

- When the CI pipeline is built, the scan runs on every change and fails on any high or critical finding (`--exit-code 1 --severity HIGH,CRITICAL`).
- The minimatch acceptance expires on 1 February 2027, when Trivy raises it again. It is removed once typescript-eslint moves to minimatch 11.
- ESLint 9 is no longer supported upstream. Upgrading to ESLint 10 is a separate task.
- `npm audit fix --force` is not used in this project, because it changes major versions without review.
- The SBOM is generated by the pipeline on each build, not committed to the repository.
